# Правила для агентов (Codex, Claude) — H3 Studio

Правила для ИИ-агентов (Claude Code, Codex), которые правят Studio или работают в ней через MCP.

## Перед началом
**Защита Mac от нагрузки:** генерацию и тяжёлую обработку видео выполнять на GPU-сервере, а не на Mac; локальные проверки ограничивать короткими и необходимыми. Не запускать тяжёлые тесты в фоне. Для FFmpeg и других дочерних процессов задавать ограничение времени и обеспечивать их завершение при отмене или тайм-ауте родителя; после прерванного теста проверить, что его процессы не остались работать. Не останавливать чужие активные задания без проверки.
1. `git status` и `git log --oneline -5`. Чужие незакоммиченные правки не коммить и не менять;
   проверь только затронутые своей задачей компоненты.
2. Вся документация — в `docs/` (вход: `docs/README.md`). Обязательно прочитай:
   `docs/STATE.md` (текущее состояние), `docs/DECISIONS.md` (решения пользователя),
   открытые пункты `docs/JOURNAL.md` (задачи от второго агента) и
   `docs/reference/STUDIO_STRUCTURE.md` (карта модулей, путь от кнопки до узла ComfyUI).
   `docs/history/` — только история, не руководство к действию.
3. Общие навыки агентов — `skills/` (см. `docs/TOOLS.md`).

## Во время работы
- **Поля режиссуры** (камера, объектив, кадр, движение, фокус, свет, цвет, стиль) — только в
  `app/director_schema.json`. Его читают и Studio, и GPU API. Не дублируй списки значений в JS/Python.
  После правки: `cp app/director_schema.json preview/h3-director/director-schema.json` (check.sh делает сам).
- **Новый функционал Studio — отдельным модулем** в `preview/h3-director/`, а не в `app.mjs`
  (это только сборка: фасад и вызовы `install*()`; части главной — `app-*.mjs`, карта в `STUDIO_STRUCTURE.md`).
  Подключай через import и передавай состояние параметрами; общие значения — `appState` из `app-state.mjs`.
- **Настройка должна доходить до узла**, а не только до текста промпта. Путь:
  Studio `settings` → `local_studio/store.py` (валидация) → `local_studio/worker.py` (поле формы +
  проверка `/api/capabilities`) → `app/main.py` (обязательный узел в `required_nodes`) → `app/graph.py`.
  Если узла нет на сервере — задание отклоняется до очереди GPU с понятной ошибкой. Молча
  «применять» нельзя.
- **Свои узлы ComfyUI** лежат в `app/comfy_nodes/…` и ставятся `scripts/install_h3_h200_overlay.sh`
  (там же список обязательных узлов, проверяемый через `/object_info`).
- **Умолчания — на качество**: полный BF16, 24 шага. Turbo, другие профили и шаги 4–50 — опции, которые выбирает пользователь.
- **Python**: никогда `pip install` в системный Python (PEP 668). Локально — `.venv` проекта,
  на сервере — venv'ы из установщиков (`ensure_venv`). venv ComfyUI не видит системный Python:
  новый пакет для узлов — с точной версией в `vendor/minimax-h3-local-studio/assets/comfy-venv-requirements.txt`.
- **Эталонные графы** (`tests/test_approved_recipe.py`, `tests/test_render_golden.py`, `tests/golden/`) меняются только
  осознанно: после правки графа пересоздай отпечатки (`python -m tests.graph_fingerprint_cases --write`).
- Интерфейс пишется по-русски; английский слой (`dom-translate.mjs`) переводит страницу по словарю `i18n/en.json`. Новую
  русскую надпись добавляй и в словарь (страница покажет её по-русски, если перевода нет). Значения (`value`) в схеме — английские, это контракт с сервером.
- После правки JS-модуля, который грузится с `?v=…`, поменяй версию в `index.html`/импорте.
- **Стиль Studio**: цвета, радиусы и шрифт — только `preview/h3-director/tokens.css` (`var(--k-*)`); кнопки —
  `.k-btn` из `components.css`. Своих палитр и `:root { --цвет }` в CSS страниц не заводить (проверяет `design-tokens.test.mjs`).

## Перед завершением
1. Проверяй только затронутые компоненты минимальным числом осмысленных тестов. Сначала один
   точечный тест или небольшой набор по реальному риску; не повторяй прогон без изменений или новой причины.
   `bash scripts/check.sh` (полный набор) запускай только перед релизом/деплоем, после изменений общего
   контракта с широким влиянием либо для диагностики конкретного регрессионного риска. Для документации
   и простых обратимых правок достаточно проверки формата/диффа; не создавай тесты ради количества.
2. Коммит с понятным описанием. Незакоммиченная работа выглядит для второго агента как чужие правки.
3. Одна строка в `docs/CHANGELOG.md`; изменился факт (сервер, снимок, умолчания, модель) — правка `docs/STATE.md`.
   Не создавай новые датированные HANDOFF/AUDIT/СВОДКА-файлы — правила ведения в `docs/README.md`.
4. `--apply` установщика сервера и перезапуск Mac Studio — только по просьбе пользователя.

## Сервер GPU
- Новый сервер с нуля (веса с Hugging Face): `bash scripts/h3_new_server.sh --host root@HOST --port PORT`
  (токен не нужен — модели открытые; подробности — `docs/reference/H3_SERVER_FROM_ZERO.md`). Со своего снимка в Cloudflare R2 —
  `bash infra/h3_up.sh --host root@HOST --port PORT` (ключи R2 в связке ключей Mac, см. `infra/h3_r2_common.sh`).
- Сверка живого сервера с репозиторием: `bash scripts/h3_server_drift.sh --host root@HOST --port PORT`.
- Без GPU: `bash infra/h3_local.sh up|start|check` (Docker-стенд для проверки графов без весов).
- Проверка всей связки без рендера: `bash scripts/verify_h3_server.sh --host root@HOST --port PORT`.
  Сверяет GPU, supervisor, веса, узлы, возможности API, совпадение `app/` с Mac, собирает граф Studio со
  всеми функциями и сверяет каждый вход с реальным `/object_info`, туннель и версию Mac Studio.
  Рендер — только после «ИТОГ: всё OK».
- Mac Studio перезапускается так: `launchctl kickstart -k gui/$(id -u)/com.minimax.h3-mac-studio`


## Не трогать
- Данные Mac Studio: `$H3_MAC_DATA_DIR` (по умолчанию `~/Library/Application Support/H3 Studio`): очередь, референсы, MP4.
- Модели на GPU (`/workspace/h3/ComfyUI/models`) — не удалять, не «чистить».
- HF-токен (`/root/.cache/h3-hf-curl.conf` на сервере) — не копировать в репозиторий.

## Замена героев в видео-референсе

Перед любой генерацией в H3 прочитай раздел «0. Язык H3» в `docs/guides/H3_PROMPT_GUIDE.md` (что модель выполняет
из задания: склейки только «At», крупность, оптика, свет, эмоции, формат) и навык `skills/minimax-video-production`.
Для длинного исходника сначала составь карту всех появлений заменяемых героев и дели сюжет на последовательные
части по склейкам исходника; первую пробу называй «часть 1/N» и не выдавай её за готовый ролик.
