# Context-IR: реализация работы с референсами

Дата исходной реализации: 2026-10-09. Обновлено: 2026-10-15.
Статус кода: `context-ir-2` интегрирован в H3 Create, а отдельные review-адаптеры подключены
к Video Look/Edit и Motion Control. Текущая read-only проверка Mac `GET /api/context-ir/capabilities`
ответила `200`: версия `context-ir-2`, workflows `h3`, `video_edit`, `motion`; `gpu_ready=false`,
`state=offline`. Поэтому код и Mac API доступны, но свежий Qwen-анализ и визуальный результат
на рабочем GPU сейчас не подтверждены.

Пользователь уточнил назначение: фото/видео-референсы, перенос движения и изменения
исходного материала. Генерация без референсов не входит в этот путь.

## Что реализовано

- Отдельная панель **«Контекст сцены»** в «Создать»: задача, «Сохранить», «Изменить
  или перенести», точные реплики, владельцы фото/видео и исполнитель в видео.
- Входы: 1–12 материалов, до 9 фото и 3 видео, каждый ролик 2–15 секунд,
  суммарно до 15 секунд. Явные роли и привязки; неоднозначные владельцы блокируют подготовку.
- Для видео FFmpeg извлекает шесть JPEG с таймкодами. Qwen получает их последовательно
  с ID и ролью источника. Это семантическое понимание выборки кадров, не извлечение поз
  каждого кадра. Полный исходный ролик остаётся входом Ref2VA для генерации.
- Локальный Qwen выдаёт структурированный план: наблюдения, начальное состояние,
  действие, конечное состояние, звук, музыка и неразрешённые вопросы.
- Изменения свойств референса требуют цитаты исходного указания. Компилятор меняет
  retention на `partially_preserved`; модель не может произвольно объявить новый запрос пользователя.
  Семантическое соответствие изменения цитате всё ещё требует просмотра человеком.
- Определения героев, метки источников, retention и шесть секций IR собираются кодом.
  Проверяются ссылки, число шотов, обязательные реплики, непрочитанные материалы и конфликты.
- Подготовка проходит через существующий диспетчер с FIFO/pause. Общие GPU admission
  и planning locks защищают вычисление Qwen от конкурирующей отправки H3.
- SQLite сохраняет снимок запроса до отправки, квитанцию и результат. Потеря ответа
  переводит операцию в сверку, не создаёт новую. Неизвестная серверу операция не
  переотправляется автоматически; после двух часов сверка завершается ошибкой.
- Полный кэш готового контекста: одинаковый снимок и профиль не запускают модель повторно.
  Seed исключён из ключа контекста. Новый бриф, владелец, файл, настройки или вариант
  инвалидируют кэш. Перезапуск GPU API меняет fingerprint: консервативная защита
  при неизвестной ревизии модели. Проверяются до 200 последних готовых результатов.
- Результат проверяется повторной локальной компиляцией. Создание видео использует
  сохранённые материалы/настройки и обычный StudioStore/worker. Повтор отправки с тем же
  client ID возвращает то же задание; квитанция вставляется атомарно вместе с заданием.
- Официальный IR проходит существующую ветку `precompiled_prompt`; второй творческий
  вызов Director не выполняется. GPU повторно проверяет манифест и формат. Сохраняются
  хэш исходного IR, ID артефакта в настройках задания и `ir_execution` — отпечатки
  фактического графа/промпта в ответе GPU.

## Файлы

- `app/context_ir/schema.py`: снимок, план, компиляция, ограничения и связи.
- `app/context_ir/engine.py`: визуальный запрос Qwen с JSON schema, один ремонт ответа,
  ограничение контекста, общие блокировки и sleep в finally.
- `app/context_ir/router.py`: capability и асинхронные серверные операции подготовки.
- `app/context_ir/store.py`: сохраняемые операции и поиск готового результата.
- `local_studio/context_ir.py`: снимок медиатеки, очередь, сверка, API, адаптер рендера.
- `local_studio/context_ir_media.py`: выборка видеокадров без изменения оригинала.
- `preview/h3-director/context-ir.mjs`: отдельная панель; в app.mjs только мост снимка.
- `tests/test_context_ir.py`: проверки значимых рисков и сквозной передачи в граф.

## API

Mac: `POST /api/context-ir/jobs`, `GET /api/context-ir/jobs`,
`GET /api/context-ir/jobs/{id}`, `POST .../{id}/cancel`, `POST .../{id}/render`.
GPU: `POST /api/context-ir/jobs`, `GET /api/context-ir/jobs/{id}`.
Capability family: `/api/capabilities.context_ir_v1`; deployed contract version is `context-ir-2` in the capability payload.

Операции подготовки и готовые артефакты доступны в панели. Новая БД `context-ir.sqlite3`
создаётся при первом использовании в каталоге данных соответствующей стороны.
В обычную БД Studio добавляется таблица `submission_receipts` для атомарной защиты
от повторной постановки. Старые задания и их рецепты не переписываются.

## Что реально проверено

- Точечные тесты: связи героев, точные реплики, неизвестные метки, изменения файлов,
  отказ при неподтверждённом изменении референса, инвалидация кэша, повторный POST,
  потеря ответа, отсутствующая квитанция, перезапуск GPU API, pause/FIFO, sleep при ошибке.
- Реальный путь Mac store → worker → GPU API → сборка графа, с подменённым ComfyUI:
  фото и фото + видео доходят до графа; повторного Qwen нет. Это проверка интеграции,
  не доказательство визуального качества.
- FFmpeg на синтетическом MP4: шесть читаемых JPEG на таймкодах
  0 / 0.38 / 0.76 / 1.14 / 1.52 / 1.9 секунды; оригинал сохранён.
- UI на изолированном стенде `18197`: открытие панели, сохранение ожидания, отмена,
  новый запрос после отмены, история после перезагрузки, постановка тестового
  артефакта в обычную очередь. Готовый артефакт для UI был явной фикстурой, не ответом Qwen.
- Рабочий Mac `18187` отвечал, GPU API `18189` и ComfyUI `18188` были недоступны.
  Реальные операции Qwen, sleep/wake на сервере и новые MP4 не проверялись.

## Границы версии

1. H3-подготовка работает в «Создать» с фото/видео. Для «Изменить видео» и Motion Control
   реализованы отдельные review-адаптеры через `context-ir-review.mjs` и `app/context_ir/edit_adapter.py`.
   Они сохраняют текущие LTX/Qwen-Edit/Ripple маршруты и не переключают эти операции на H3.
   Capability Mac перечисляет `h3`, `video_edit`, `motion`; GPU-исполнение требует отдельной
   совместимой capability и сейчас недоступно.
2. Точная замена героя и покадровое движение не гарантируются. Для замены действует
   существующий контракт режима replace и capability Character Swap; для движения
   — нативные видео-референсы. Ограничения сервера не обходятся.
3. Один назначенный исполнитель на видео в текущем контракте Context-IR. Несколько
   целей внутри одного ролика не поддерживаются; неоднозначность следует исправить.
4. Отдельные аудиореференсы и видео «Продолжение» пока не входят в этот путь. Если включён
   звук видео-референса, оригинальный звук передаётся H3, но Context-IR его не прослушивает.
5. Отдельного evidence-кэша каждого материала и частичного перепланирования пока нет:
   изменение реплики запускает новый запрос модели, полный совпавший контекст берётся из кэша.
6. Камера/оптика в существующей ветке официального IR передаются текстом; цвет, film look,
   guide frames и доступные эффекты сохраняют свои существующие пути в граф.
7. Исходный бриф, поля сохранения/изменения и визуальные наблюдения могут быть поняты
   моделью неверно. Проверка синтаксиса не доказывает выполнение замысла. Оценка по MP4 обязательна.
8. Рабочие службы не перезапускались. Для использования нужны обновлённые Mac Studio и
   GPU API; установщик уже включает каталог app/ целиком. Перед применением — сверка
   очередей и `scripts/verify_h3_server.sh`, затем ограниченный согласованный A/B.

Полная целевая архитектура: [H3_CONTEXT_IR_ARCHITECTURE.md](H3_CONTEXT_IR_ARCHITECTURE.md).

Итог проверки кода: `bash scripts/check.sh` — 249 JS, 765 Python, 77 subtests;
3 skipped; «OK — всё зелёное». Временный UI-стенд остановлен после проверки.

## Дополнение 2026-10-09: редакторы видео и Motion Control

Контракт обновлён до `context-ir-2` (ключ capability `context_ir_v1` сохранён как адрес
семейства; версия проверяется отдельно). Поле `edit` задаёт backend-neutral intent:
`video_edit` с явными изменениями и ссылкой каждого изменения на фото, либо `motion`
с одним персонажем, явно выбранным исполнителем и источником окружения.
Для edit анализируется начало исходного видео до 10 секунд. Хэш проверяется по
полному исходному файлу. Реплики не добавляются: редактор сохраняет исходную дорожку.

`app/context_ir/edit_adapter.py` компилирует отдельный manifest `execution`: стадии
Qwen Image Edit (первый кадр + максимум два фото), инструкцию Ripple, источник,
длительность анализа и требование проверки кадра. Секции и метки H3 в LTX не идут.
Каждая video_edit-правка должна совпасть с точной исходной цитатой и назначенным
референсом; неизвестные/лишние правки блокируются. Motion binding создаётся кодом:
модель не выбирает другого исполнителя. Лимит текста проверяется после штатного
`compose_prompt`. Sampler, графы, веса и профили качества не меняются.

В двух рабочих пространствах появилась дополнительная панель «Разобрать референсы
и проверить план». Анализ → проверка → принятие плана → подготовка кадра → просмотр
кадра → рендер. Можно явно продолжить без анализа с прежними настройками редактора.
Принятие привязано к исходнику/референсам/инструкциям. Старый план не используется
при изменении этих полей. `GET /api/context-ir/jobs/{id}/execution` повторно проверяет
файлы и компиляцию; `/render` запрещён для edit-контекста (никакого случайного H3).

Motion Control теперь использует сохранённые intent/receipt через общий
`video-look-flow`: сначала только кадр, видео — по кнопке подтверждения. Потерянный
POST сверяется без слепого повтора. Идентификатор кадра и принятый manifest сохранены
в черновике; редактирование во время отправки заблокировано. Существующие результаты
Motion Control остаются в прежней истории.

Проверено: 19 точечных Python-тестов Context-IR, включая адаптеры, неверные привязки,
изменённые файлы, запрет H3-запуска и tampered manifest; существующие JS-тесты потери
ответа/восстановления. Полный check.sh: 249 JS, 768 Python, 3 skipped, 77 subtests.
Браузерный изолированный стенд: реальные загрузки синтетических MP4/PNG, постановка
анализа обоих рабочих пространств, восстановление после reload, принятие manifest,
реальная постановка только keyframe, просмотр fixture-кадра без видео-задания.
**Результат модели и готовый кадр в UI были fixtures, не GPU-генерацией.**

Остаётся внешняя приёмка: совместимый Mac/GPU deployment, настоящий анализ Qwen и
ограниченные reference/photo, motion и video-edit рендеры с визуальной оценкой.
На момент проверки Mac18187 здоров, GPU18189 недоступен. Перезапуск production,
установка нод и реальные рендеры не выполнялись. Отдельный кэш evidence/embeddings,
точный pose/flow motion capture и аудиоанализ по-прежнему не реализованы. Ускорение
денойзинга и визуальная стабильность лиц этой проверкой не доказаны.
