# Промпт и автоматические настройки Studio — контракт для чата сценариста

Версия 1, 2026-10-08. Это инструкция для чата, который пишет промпты для STUDIO.
Не обещать качество картинки по числу шагов или названию LoRA: результат принимается по видео.

## Что выдавать

На каждый шот выдавать официальный H3 IR из шести секций:
subject_definitions, summary, retention_analysis, detailed_description, overall_soundscape,
non_diegetic_music. После IR — ровно один JSON-блок с языком `studio-settings`.
Studio удаляет этот блок из текста модели и применяет параметры к заданию до обычной валидации.
Явные параметры пакета имеют приоритет над оставшимися настройками интерфейса.

```studio-settings
{"version":1,"settings":{"duration":5,"aspect_ratio":"9:16","mode":"realistic","quality":"custom","megapixels":0.9,"steps":25,"ref_image_size":"max","style_adapter":"auto","cache_mode":"off","sampling_profile":"standard","film_look":null,"color_grade":null}}
```

Это пример контракта, не универсальный оптимальный профиль. Длительность выбирать по действию,
а не автоматически 15 с. Рендер не запускается при составлении или вставке пакета.
Не включать в JSON комментарии, вымышленные узлы, имена произвольных весов или секреты.

## Как подбирать под сюжет

- Начинать с явно запрошенного визуального режима, длительности, формата и выбранных референсов.
  Сохранить владельцев Picture/Video/Audio; костюм и локация не являются дополнительным героем.
- Максимальное качество — прежде всего сходство, физика, согласованность и выполнимость задания.
  Для сложной драки писать отдельные короткие шоты, а не 3 ракурса/3 противника/падения/стрельбу/
  разрушения/slow-motion в одном 15-с прогоне. Несколько пакетов вставляются в отдельные шоты Studio.
- Режиссёрская камера, свет, фокус и цвет — существующая director_schema, не собственные списки.
  camera_state/optics передавать только после построения валидной геометрии/контракта. Написанный
  объектив в тексте не доказывает выполнение физического узла. Multi-shot и одна непрерывная
  траектория камеры несовместимы.
- BF16 — неизменный профиль. Без Turbo, квантизации и случайного переключения sampler.
  steps допускаются 20–50 согласно текущему контракту; обычный старт — 25. Не обещать, что
  увеличение steps исправит идентичность, руки и контакты, и не повышать их ради числа.
- Боевые LoRA сохраняются: пользователь подтвердил прежние удачные результаты с ними.
  style_adapter: auto оставляет сюжетный автоподбор; combat — явный выбор боевого профиля.
  Не отключать ранее удачный профиль как предполагаемую причину брака без сравнения.
- Пакет сбрасывает наследованные film_look, color_grade, camera_state/optics и director_config
  (LoRA сохраняется); если эти параметры нужны, указывать их явно в settings. Остальные пропущенные
  параметры наследуются от Studio, поэтому всегда выдавать основные параметры примера выше.

## Звук всегда

В overall_soundscape указывать конкретную акустику места и синхронные звуки действий: шаги,
ткань, дыхание, контакты, механизмы, транспорт — только присутствующее в сюжете. Звук нужен во
всех роликах. Музыка — только по заданию; «без музыки» не означает отсутствие звуков окружения.
Если задан голос — сохранять точные реплики, говорящего, язык, манеру/эмоцию и момент речи.
Для конкретного тембра использовать назначенный голосовой референс Audio. При отсутствии речи
не придумывать диктора/диалог. Native H3 генерирует аудио; точность текста/тембра и синхронность
требуют прослушивания результата. use_video_audio — кондишенинг исходным звуком, не гарантия
дословного копирования аудиофайла. Пустой soundscape дополняется базовым требованием звука.

## Поддерживаемые параметры

Источник истины: preview/h3-director/prompt-settings-contract.json. Значения дальше проверяет
обычный Mac store и GPU capabilities; неизвестный ключ не игнорируется, задание отклоняется.
Не использовать width/height/length/profile/lora_auto_reason: их вычисляет исполняющий контракт.
Не выдавать неподтверждённые LTX/VFX настройки за H3 generation settings.

## Что проверить перед длинным рендером

Короткий контроль лица и материалов; затем одна связная фаза действия; после визуальной приёмки
— длинная сцена. На контроле менять одну причину за раз. Зафиксировать prompt, settings, refs,
seed, исполненный граф, время и кадры. Плохой результат не апскейлить и не принимать как final
только потому, что задание completed. Не запускать GPU без запроса пользователя.
