# Передача H3-заданий заранее

Studio передаёт готовые H3-задания и все их референсы на сервер, не ожидая завершения предыдущего ролика. После подтверждения «На сервере · Mac можно отключить» этот ролик не зависит от соединения с Mac. Пока статус «передача» или локальное ожидание, файлы ещё не приняты полностью. Перед отключением Mac убедиться, что все нужные задания приняты сервером.

Mac остаётся владельцем творческого проекта и истории; сервер хранит очередь исполнения. После восстановления связи Studio сверяет immutable client ID, получает настоящий ComfyUI ID и скачивает MP4. Пауза Mac останавливает новые передачи; уже принятые сервером задания продолжают выполняться. Отмена конкретного задания передаётся на сервер.

Фоновая сверка Studio каждые 15 секунд просматривает все принятые H3-задания с известным remote ID и скачивает готовый MP4, даже если более ранний ролик ещё рендерится. Файл проходит штатную проверку и атомарно попадает в `results/` с квитанцией своего задания. Чужие серверные файлы без квитанции Studio автоматически не импортируются: у них нет надёжной привязки к сцене и франшизе.

## Реализация

- `local_studio/worker.py`: независимый `stage_once` передаёт локальное ожидание параллельно наблюдению за активным GPU-роликом. Guarded transitions, lookup и запрет неоднозначного повтора сохранены.
- `app/server_queue.py`: временная загрузка → проверка всех SHA-256 → fsync файлов и атомарной квитанции → ACK. Хранилище `/workspace/h3/api-data/server-queue/<clientUUID>/`. Изменённый payload с тем же ID отклоняется409.
- `app/server_queue_service.py`: отдельный supervisor `h3-server-queue`, только loopback18191. Диспетчер самостоятельно вызывает существующий GPU API18189 после освобождения ComfyUI. Исходные поля, промпт, роли, seed, sampler/cache и путь Qwen не подменяются.
- До передачи графа renderer сохраняются копии всех входов. После подтверждённого приёма renderer копии intake освобождаются; основная квитанция остаётся. Подготовленные входы renderer и исходники Studio сохраняются.
- `scripts/install_h3_server_queue.sh`: установка только нового сервиса, без рестарта API/ComfyUI. Включён в overlay bundle.
- `infra/h3_server_queue_tunnel.sh` и `scripts/install_h3_server_queue_tunnel.py`: отдельный LaunchAgent, следующий текущему SSH endpoint и ключу основного туннеля. Исполняемый скрипт копируется в Application Support, поскольку macOS запрещает LaunchAgent читать Documents напрямую. Основной туннель не заменяется.
- `H3_SERVER_QUEUE_URL` задаёт endpoint intake для нестандартного GPU API адреса. Для стандартного Mac18189 используется18191. Проверяется capability, старые серверы сохраняют прежнее поведение.

Это очередь готовых H3-роликов. Генерация отсутствующих референсов, зависимые шаги Production, Context-IR, keyframes, audio и edit сохраняют собственные существующие диспетчеры; их независимое выполнение без Mac данным изменением не заявляется.

## Проверка и восстановление

`bash scripts/check.sh`; затем `scripts/verify_h3_server.sh` проверяет также новый supervisor и capability. Реальные входы и статусы сверять по clientUUID в `/api/server-queue/jobs/<UUID>`.

Ожидающие intake-задания переживают перезапуск диспетчера. Если процесс оборвался в момент передачи в renderer, сначала lookup в его постоянном registry; при неопределённом результате — needs_reconciliation, без автоматического повторного рендера. Перезапуск ComfyUI и потеря уже выполнявшегося графа не объявляются безопасным восстановлением самим intake.
