# Режиссура из промпта

В Studio можно вставить один блок `[Режиссура] … [/Режиссура]` в любом месте описания кадра. Карточки переключаются при вводе/вставке. Без блока сохраняется обычное управление карточками.

```text
[Режиссура]
Камера: Авто
Объектив: lens.85
Кадр: shot.close
Движение: movement.push
Фокус: focus.auto
Свет: lighting.overcast
Цвет: color.desaturated
Стиль: style.realism
[/Режиссура]

<Picture 1> — внешность героя.
Герой замечает знакомого, замирает, затем сдержанно улыбается.
```

Названия полей: Камера, Объектив, Кадр, Движение, Фокус, Свет, Цвет, Стиль. Допускаются английские ключи категорий. Значение — точный ID пресета, русское название карточки, её английское название или `Авто`. Дополнительно понимаются «Крупный план» и «Медленный наезд» из первого согласованного примера.

В каталоге движения есть 46 пунктов по категориям: Dolly/Track, Zoom/Lens, Drone/Crane, Pan/Tilt, Physical Moves, Human Camera и Specials. Они находятся в `app/director_schema.json`, откуда Studio формирует карточки и проверяет ID. Для камеры в промпте используй `Movement: <ID движения>`, `Speed: slow|medium|fast`, `Framing: <ID начального кадра>` и `End: <ID конечного кадра>`. `Speed` задаёт параметр движения и масштаб траектории `camera_state`; `End` задаёт конечную крупность в `director_config` и траекторию там, где она поддерживается. Камера остаётся отдельно от описания сюжета и действия героя.

Пример: наезд из общего плана в крупный. Идентификаторы должны существовать в каталоге Studio:

```text
[Режиссура]
Movement: movement.dolly_in
Speed: slow
Framing: shot.full
End: shot.close
[/Режиссура]

<Picture 1> — внешность героя.
Герой открывает дверь и замечает человека в коридоре.
```

Такой блок держит камеру отдельно от действия героя. `Framing` задаёт начальную композицию, `End` — конечную крупность. Если при Speed/End пропущены Movement/Framing, Studio автоматически выбирает начальный средний кадр (общий по телу для End: shot.medium) и наезд либо отъезд по разнице крупности. Явные значения остаются приоритетными; статичная/неподдерживаемая камера по-прежнему проверяется. Автоподбор виден под промптом. `Speed` меняет траекторию движения; для наезда и зума с `End` задаёт, к какому времени достигается конечная композиция. Наезд, зум, панорама, наклон, дуга/облёт, слайдер и вертикальный проезд создают геометрию `camera_state`. Следование, handheld, таймлапс и специальные переходы передаются как конкретная текстовая режиссура. По умолчанию GPU компилирует геометрию `camera_state` в текст H3; видеогид H3CameraGuide остаётся capability-gated.

Каталог движения читается из `director_schema.json`; карточки с ID создаются из него, поэтому отдельный список camera-move значений в JS/Python не поддерживается. Остальные категории используют DIRECTOR_PRESETS и пользовательские пресеты. Список названий и ID показывается под промптом в «Настройки из промпта · синтаксис». Там же кнопка «Вставить блок из карточек». Для чата предпочтительны ID: они однозначны даже при одинаковых названиях собственных пресетов.

## Правила для чата, который пишет промпт

- Выдай один полный блок режиссуры и описание сцены за его пределами.
- Используй только ID из актуального каталога Studio. Не придумывай параметры/пресеты.
- Для камеры используй `Movement`, `Framing` и `End` с каталоговыми ID; `Speed` задавай как `slow`, `medium` или `fast`.
- Если параметр не задан автором, используй `Авто` или пропусти поле. Недостающие зависимости Speed/End Studio подставляет автоматически.
- Не задавай одно поле дважды.
- Не противоречь сцене: статичная камера несовместима с наездом; крупность, фокус, стиль и освещение должны соответствовать описанию.
- Сохраняй сюжет, эмоции, время действия и реальные теги `<Picture N>` / `<Video N>`.

## Приоритет и ошибки

В режиме с блоком пропущенные поля становятся «Авто», предыдущие выборы не наследуются. Ручное изменение карточки/профиля переписывает блок (сцену оставляет без изменений). При удалении блока сохраняется последний выбор карточек — это возвращение к обычному управлению.

Неизвестные строки, отсутствующий/повторный блок, повторное поле и неподдерживаемые значения показывают ошибку и блокируют отправку. Незавершённый блок при наборе не меняет карточки. Сохранённый черновик с блоком синхронизируется при загрузке/выборе сцены.

Проверяются существующие несовместимости пресетов и явная фраза «камера неподвижна/статична/зафиксирована» при выбранном движении. Это ограниченная проверка: произвольные смысловые противоречия, сложный монтаж и все языки автоматически не распознаются.

## Передача в H3

Перед созданием задания parser ещё раз проверяет блок. Сами служебные строки блока удаляются из текста, а выбранные пресеты проходят существующий путь: director_config → worker → GPU API → граф. CameraGuide/оптика, цвет/плёнка и текст режиссуры используют те же карточки. Сюжет/референсы остаются в промпте. Это не новые возможности узлов и не гарантия буквального исполнения моделью.

## Проверки и откат

`node --test preview/h3-director/prompt-direction.test.mjs` проверяет весь каталог, Auto, ошибки, собственные пресеты, сохранение истории и передачу настроек в конфигурацию/камеру. `bash scripts/check.sh` — общий gate.

UI проверяется в изолированном статическом предпросмотре без GPU-запуска и без записи рабочего черновика. Изменение фронтенда отдаётся действующим Mac Studio без перезапуска процесса; требуется обновление страницы. Откат — revert коммита этой функции.

## Автоматическое согласование монтажных кадров

Для нескольких разных [Shot N] Studio автоматически убирает общую camera_state/camera_optics
и глобальные movement/shot/lens/focus из director_config. Операторские указания каждого кадра
остаются в исходном промпте H3; остальные настройки (актёрская игра, свет, цвет, LoRA) сохраняются.
Это текстовая режиссура отдельных кадров, а не физическая траектория через монтажные склейки.
Повторные упоминания одного [Shot N] не считаются несколькими кадрами.
